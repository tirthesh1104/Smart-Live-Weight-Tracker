## 5. Synchronization & Safe Upsert Architecture

1. **Idempotent Upsert Logic**:
   - Monitored trains use the unique business key `number` (e.g. `12101`, `11020`, `12115`, `12951`, `12301`).
   - If the train exists, metadata (`name`, `from_station`, `to_station`) is updated via `PATCH`.
   - If not present, a new row is created via `POST`.
2. **Coach Formation Mapping**:
   - Raw rake formation strings (e.g. `ENG-VP-LPR-GEN-GEN-H1-A1-B1..B5-PC-S1..S8`) are parsed.
   - Repeated tokens are indexed (`GEN-1`, `GEN-2`, `LPR-1`, `LPR-2`) to satisfy the `(train_id, coach_no)` composite unique key constraint.
   - Coach types are mapped into database check constraints: `'Sleeper', 'AC 3 Tier', 'AC 2 Tier', 'General', 'Second Sitting', 'Pantry Car', 'Engine'`.
3. **Audit Trail**:
   - Every sync operation appends an entry to the synchronization log history in memory and logs into Supabase `audit_logs`.

## 6. Real vs Simulated Data Demarcation

In strict accordance with project rules:
1. **Third-Party Railway Data** (Train names, numbers, routes, station stops, platform numbers, scheduled arrival/departure, rake coach positions, and live delays) are labeled:
   `Source: RailRadar (NTES Official)` or `Source: RailCore IRCTC Developer API`.
2. **Coach Weight & Passenger Crowding Data**:
   - Third-party APIs do **not** provide actual coach weights or passenger headcounts.
   - Physical weight measurements and passenger occupancy estimates are provided by the hardware simulation bench and are prominently stamped:
   > **`[SIMULATED SENSOR DATA]`**: *Bogie strain gauge measurements, weight distribution percentages, and passenger headcount projections are generated in real-time by the hardware test bench simulator and remain strictly isolated from real railway scheduling APIs.*

## 8. Remaining Limitations & Honest Reporting

1. **Third-Party API Plan Limits**:
   - RailCore IRCTC API operates under a 2,000 requests/month quota. TTL in-memory caching (24 hours) protects this allowance.
   - RailRadar NTES directory is refreshed hourly to prevent redundant upstream requests.
2. **Qrail Provider Status**:
   - Upstream Qrail credentials return `UnAuthorized Request` (HTTP 401). Qrail remains marked `UNAVAILABLE` until fresh credentials are provided.
3. **Physical Weight Sensors**:
   - Live weight readings are sourced from the dedicated Bogie Strain Gauge Simulator Bench. Physical trackside load-cell sensors are not physically installed on Indian Railways rolling stock in this prototype environment.
